### 1.AMM：没有订单薄，靠数学定价

传统交易所：

~~~
买单：
100 BTC @ 100000

卖单：
2 BTC @ 100100
~~~

然后：

~~~
撮合引擎 -> 价格优先 -> 时间优先 -> 撮合
~~~

这就是之前做的CEX。

而AMM 不需要传统订单薄。

最经典的：

>  x * y = k

例如池子：

~~~
ETH/USDC

100 ETH
200000 USDC
~~~

那么：

~~~
x * y = 100 * 200000
			= 20000000
~~~

有人买ETH：

~~~
ETH 减少
USDC 增多
~~~

池子会根据公式重新计算 ETH/USDC 的比例。

所以：

>  AMM 本质上是用池子的资产比例 + 数学公式完成定价和交易。

### 2.AMM为什么会产生滑点？

假设池子：

~~~
100 ETH
200000 USDC
~~~

ETH 价格：

~~~
2000 USDC
~~~

你想买：

~~~
1 ETH
~~~

价格可能接近：

~~~
200000/(100-1) = 2020
~~~

但如果你想买：

~~~
50 ETH
~~~

那就不可能还是2000。

因为你正在大量改变池子的：

~~~
ETH / USDC
~~~

比例。

所以：

>  交易规模越大，相对于池子流动性越大，价格冲击通常越大。

这就是：

**滑点 Slippage。**

### 3.滑点和价格影响不是完全一回事

这个后面需要好好区别一下：

#### Price Impact

因为你的交易本身改变了池子的价格。

比如：

~~~
ETH = 2000
~~~

买很多ETH：

~~~
2000 -> 2050 -> 2100
~~~

这是：

> Price Impact

#### Slippage

你原本预计：

~~~
2000
~~~

最后实际成交：

~~~
2030
~~~

这就是：

> Slippage

用户经常设置：

~~~
Slippage tolerance = 0.5%
~~~

意思是：

> 我最多接受0.5% 的成交价格偏差

### 4.借贷 Lending

DeFi 借贷其实非常容易理解：

~~~
用户 A -存ETH-> Lending Protocol -借USDC-> 用户 A
~~~

但是协议会问一个问题：

> 你不还钱怎么办？

传统银行：

~~~
信用
工资
征信
抵押物
~~~

DeFi 没有传统意义上的人工催收。

所以主要靠：

> 超额抵押 + 自动清算

### 5.抵押率

假设：

~~~
你抵押 ETH = $10000
借 USDC = $5000
~~~

那么：

~~~
抵押率 = 抵押物价值 / 借款价值
			= 10000 / 5000
			= 200%
~~~

也就是：

> 你拿2块钱资产，借1块钱

### 6.LTV

LTV:

> Loan To Value

公式：

~~~
LTV = 借款价值 / 抵押物价值
~~~

上面的例子：

~~~
5000 / 10000
= 50%
~~~

所以：

~~~
抵押率 = 200%
LTV = 50%
~~~

他们的本质上是倒数关系：

~~~
Collateral Ratio = Collateral / Debt

LTV = Debt / Collateral
~~~

### 7.LTV为什么重要？

假设协议规定:

~~~
最大 LTV = 75%
~~~

你有：

~~~
ETH = $10000
~~~

最多借：

~~~
$7500
~~~

因为：

~~~
7500 / 10000
= 75%
~~~

如果ETH 跌到：

~~~
$8000
~~~

你的债务还是：

~~~
$7500
~~~

于是：

~~~
LTV = 7500 / 8000
		= 93.75%
~~~

风险已经非常高。

### 8.清算阈值

这个非常重要。

假设：

~~~
最大 LTV = 75&

Liquidation Threshold = 80%
~~~

可以理解为：

~~~
LTV < 75% => 安全

LTV -> (75% - 80%) => 风险越来越高

LTV >= 80& => 可以清算
~~~

所以：

> LTV 是当前债务占抵押物价值的比例

而：

> 清算阈值是协议允许你把风险推到什么程度

### 9.健康因子 Health Factor

这个概念需要掌握，Aave这类协议经常用：

一个简化理解：

~~~
Health Factor = 抵押物价值 * 清算阈值 / 债务价值
~~~

例如：

~~~
抵押物 = $10000

清算阈值 = 80%

债务 = $5000
~~~

那么：

~~~
HF = 10000 * 80% / 5000
	 = 1.6
~~~

所以：

~~~
HF > 1
~~~

安全。

如果：

~~~
HF < 1
~~~

理论上已经进入可清算区域。

### 10.把这几个概念放一起

这是现在最应该形成的一个图：

~~~
                抵押物价值
                    │
                    ▼
                 $10,000
                    │
          ┌─────────┴─────────┐
          │                   │
          ▼                   ▼
        借款                 清算阈值
       $5,000                  80%
          │
          ▼
        LTV
       50%
          │
          ▼
   Health Factor
       1.6
~~~

其中：

~~~
LTV = Debt / Collateral
~~~

而：

~~~
Health Factor = Collateral * Liquidation Threshold / Debt
~~~

### 11.为什么DeFi 要超额抵押？

因为没有人知道：

> 明天ETH 是 5000 还是 2000.

所以不能：

~~~
抵押 $100
借   $100
~~~

否则：

~~~
ETH 下降 20%
~~~

协议马上出现：

~~~
抵押物 = $80
债务 = $100
~~~

出现：

> 坏账

所以DeFi 常见：

~~~
抵押 $100 -> 最多借 $60-$80
~~~

给价格波动留出缓冲。

### 12.Oracle（预言机）

这就出现了一个非常关键的问题：

> 协议怎么知道ETH 现在值多少钱？

因为只能合约自己不知道：

~~~
ETH/USD = ?
~~~

所以需要：

Oracle

Oracle就是：

> 把链下/外部世界的数据安全地带到链上。

例如：

~~~
Biance
Coinbase
Kraken
DEX
其他市场
      │
      ▼
   Oracle
      │
      ▼
Ethereum
      │
      ▼
Lending Protocol
~~~

例如：

~~~
ETH Price = $2500
~~~

借贷协议用这个价格计算：

~~~
抵押物价值
LTV
Health Factor
Liquidation
~~~

### 13.Oracle为什么是DeFi 的命门？

因为：

~~~
Oracle Price -> 抵押物价值 -> Health Factor -> Liquidation
~~~

如果 Oracle：

~~~
ETH = $2500
~~~

突然错误变成：

~~~
ETH = $500
~~~

那么：

~~~
抵押物价值暴跌 -> 大量账户 HF < 1 -> 大量清算
~~~

甚至可能造成：

> 协议级灾难

所以DeFi 协议非常重视:

~~~
Oracle mainpulation
Price mainpulation
TWAP
Price deviation
Stale price
~~~

### 14.清算

假设：

~~~
Alice:
	抵押 ETH = $10000
	借 USDC = $7000
	
	LTV = 70%
~~~

ETH 跌了。

现在：

~~~
ETH = $8000
~~~

那么：

~~~
LTV = 7000 / 8000
		= 87.5%
~~~

如果：

~~~
Liquidation Threshold = 80%
~~~

Alice:

~~~
进入清算
~~~

### 15.谁来清算？

通常是：

> Liquidator

例如：

~~~
Alice -> 抵押ETH -> 借USDC -> ETH下跌 -> HF<1 -> Liquidator -> 偿还 Alice的部分债务 -> 拿走一部分抵押物 -> 获得 Liquidation Bonus
~~~

比如：

~~~
偿还债务：$1000

拿走抵押物：
$1050
~~~

多出来：

~~~
$50
~~~

就是激励。

这样协议就不需要人工找人清算。

### 16.坏账 Bad Debt

这是DeFi 最危险的东西之一。

假设：

~~~
抵押物 = $100
债务 = $90
~~~

突然市场暴跌：

~~~
抵押物 -> $50
~~~

但是债务：

~~~
$90
~~~

这时候：

~~~
抵押物价值 < 债务
~~~

即使全部卖掉抵押物：

~~~
只能拿回 $50
~~~

还差：

~~~
$40
~~~

这个：

> $40 就可能成为坏账。

### 17.为什么会产生坏账？

常见原因：

~~~
极端行情 + Oracle延迟 + 市场流动性不足 + 清算速度不够 + 价格滑点
~~~

例如：

~~~
BTC -> $100000 -> $80000 -> $60000
~~~

价格瞬间暴跌。

清算机器人：

~~~
来不及清算
~~~

或者

~~~
想卖 $10M ETH
~~~

但市场只有：

~~~
$2M 流动性
~~~

于是大量：

~~~
Price Impact
Slippage
~~~

最终：

~~~
抵押物卖不出足够的钱
~~~

产生坏账。

### 18.资金费率Funding Rate

这个和前面的借贷不是一回事。

他主要出现在：

> 永续合约 Perpetual

因为永续合约没有到期日。

BTC 永续可以：

~~~
一直持有
~~~

那怎么让：

~~~
BTC Perp Price
~~~

跟：

~~~
BTC Spot Price
~~~

保持相近？

靠：

Funding Rate

例如：

现货：

~~~
BTC = $100000
~~~

永续：

~~~
BTC Perp = $102000
~~~

说明：

~~~
永续明显高于现货
~~~

市场可能：

~~~
多头太多
~~~

于是：

> 多头支付资金费给空头。

这样鼓励：

~~~
多头减少
空头增加
~~~

最终：

~~~
Perp Price -> Spot Price
~~~

靠近。

### 19.Funding Rate 的本质

你可以简单理解：

> 资金费率是多空之间定期支付的费用，用来让永续合约价格锚定现货价格。

所以：

~~~
Funding > 0
~~~

通常：

~~~
Long -> Pay -> Short
~~~

而：

~~~
Funding < 0
~~~

通常：

~~~
short -> Pay -> Long
~~~

### 20.把永续合约串起来

这其实就是项目里的核心：

~~~
用户开仓 -> 保证金 -> Position -> Mark Price -> Unrealized PnL -> Maintenance Margin -> Health / Margin Ratio  -> Liquidation
~~~

同时：

~~~
Funding Rate -> 定期结算 -> (Long <-> Short)
~~~

而：

~~~
Oracle / Mark Price
~~~

决定：

~~~
PnL
Liquidation
Funding
~~~

所以 Oracle 对永续同样非常重要。

### 22.容易混淆的几个概念

列表：

| 概念          | 本质                 | 核心问题                      |
| ------------- | -------------------- | ----------------------------- |
| AMM           | 数学定价 + 流动性池  | 没订单薄怎么交易？            |
| 滑点          | 实际成交价格偏离预期 | 这笔交易到底成交多少？        |
| Oracle        | 外部价格数据         | 合约怎么知道 BTC/ETH 多少钱？ |
| 抵押率        | 抵押物 / 债务        | 我拿多少资产借了多少钱？      |
| LTV           | 债务 / 抵押物        | 我的杠杆有多高？              |
| 清算阈值      | 允许风险达到的上限   | 什么时候允许清算？            |
| Health Factor | 综合偿债安全指标     | 我现在离清算还有多远？        |
| Liquidation   | 强制偿还债务         | 用户快还不起了怎么办？        |
| Funding Rate  | 多空定期资金交换     | 永续怎么锚定现货？            |
| Bad Debt      | 抵押物不足以覆盖债务 | 清算之后还欠钱怎么办？        |
