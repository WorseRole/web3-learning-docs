## 1. 总句

**用户只认 Proxy 地址；代码在 Implementation（delegatecall），状态在 Proxy；开业 `ERC1967Proxy + initialize`，升级 `upgradeToAndCall`，不 new 第二个 Proxy。**

---

## 2. delegatecall

用 Implementation 的 **代码**，改 **Proxy 的 storage**。用户对 **Proxy** 发交易，不要对 impl 做业务验收。

---

## 3. 部署 vs 升级

| | Day 13 | Day 14 |
|--|--------|--------|
| Proxy | `new ERC1967Proxy(v1, initData)` | 同一地址 |
| impl | V1 | 新 V2 |
| 关键 | `encodeCall(initialize, owner)` | `upgradeToAndCall(v2, data)` |

---

## 4. Day 13 四 API

**ERC1967Proxy** · **encodeCall(initialize)** · **__Ownable_init** · **_disableInitializers**

---

## 5. UUPS

- **`upgradeToAndCall`** 在 **Implementation（UUPSUpgradeable）**，经 Proxy delegatecall 执行。  
- **`_authorizeUpgrade`**：`onlyOwner` 等权限。  
- **变砖**：新 impl 无 UUPS → Proxy 无法再升级。

---

## 6. Layout 与 init

V2 **兼容** V1 变量顺序；新字段 **末尾追加**。升级用 **`reinitializer` / initializeV2**，勿再调首次 **`initialize`**。

---

## 7. 升级风险（3 条）

Storage 冲突 · 初始化 / 锁 impl · 权限与 UUPS 保留
